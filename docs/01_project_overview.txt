 1. 프로젝트 한 줄 요약
────────────────────────────────────────────────────────────────────────────

  "이탈리아 식품 브랜드 Mulino Bianco가 한국 시장에 진출한다고 가정하고,
   EU 기준 ERP 시스템을 한국 식품 법규에 맞게 현지화(Localization)한 뒤,
   그 위에 AI 에이전트를 얹어 구매·공급망·품질 업무를 자동화한
   가상의 ERP 시스템이다."

────────────────────────────────────────────────────────────────────────────
 2. 기획 의도
────────────────────────────────────────────────────────────────────────────

  ● 단순히 기존 브랜드를 따라 만드는 것이 아니라,
    "한국에 들여온다"는 시나리오를 잡아서 신선함과 스토리를 확보

  ● SAP 컨설턴트의 실제 핵심 업무 중 하나가 바로
    "글로벌 ERP 템플릿을 각 나라 법규/관행에 맞게 현지화"하는 작업.
    해당 프로젝트는 그 과정을 직접 설계로 시뮬레이션함.

  │       └─ QC            : 알레르겐/온도이탈/리콜                      │
  │       → 역할 정의는 스킬(SKILL.md), 백엔드 접근은 Zig CLI(mulino)   │

                                  │
  ┌───────────────────────────────▼────────────────────────────────────┐
  │  L3 : 자연어 대시보드                                               │
  │       사용자가 자연어로 질문 → 의도 분석 → 차트/대시보드 자동 생성  │
  └────────────────────────────────────────────────────────────────────┘


────────────────────────────────────────────────────────────────────────────
 5. ERP 데이터 모델 (L0) — 30개 테이블 (+1개 규제 뷰)
────────────────────────────────────────────────────────────────────────────

  [공급업체/원자재]
    suppliers               원자재 공급업체
    supplier_certifications 공급업체 인증서 (HACCP/GMP 등, 유효기간 체크)
    allergens               알레르겐 마스터 (19개 법정군 - 22종 계층)
    raw_materials           원자재 (자재유형: 원료/포장재/첨가물)
    raw_material_allergens  원자재-알레르겐 매핑 (복합 UNIQUE)

  [구매/입고]  ← SAP MM
    purchase_orders         발주 헤더 (국세청 전자세금계산서)
    purchase_order_items    발주 상세 (수량 양수 CHECK)
    inbound                 입고 내역 (기본 HOLD 상태, QC 결정 메타데이터)
    inbound_temperature_logs 입고 운송 온도 로그 (센서 ID, BRIN)
    raw_material_lots       원재료 LOT (추적 핵심, 잔여량 음수방지)

  [창고]  ← SAP EWM
    warehouses              창고/플랜트 (상온/냉장/냉동, 상위구역 계층)
    warehouse_temperature_logs 창고 온도 모니터링 (BRIN 인덱스)
    stock                   완제품 현재 재고 (제품-창고 복합 UNIQUE)

  [생산]  ← SAP PP
    production_records      생산가공기록 (공정 파라미터 JSONB)
    production_ingredients  투입 원재료 추적 (소모량 양수 CHECK)
    production_lots         생산 LOT (완제품/반제품 다단계 BOM)
    products                제품 마스터 (품목보고번호, 이력등록번호)

  [수주/출고]  ← SAP SD
    customers               거래처 마스터
    orders                  수주 헤더 (전자세금계산서)
    order_items             수주 상세
    outbound                출고 내역
    outbound_lots           출고 LOT 추적 (출고수량 정합성 불변)

  [품질 & 알람]  ← SAP QM
    recalls                 리콜 관리 (생산LOT 또는 원재료LOT 타겟)
    alert_rules             품질/온도 임계치 동적 규칙
    alert_events            품질 이상/온도 이탈 이벤트

  [거버넌스 영속화]  ← SAP GRC
    governance_actions      액션 승인 요청 큐 (다단계/우선순위/페이로드)
    governance_decisions    승인/반려 의사결정 이력
    governance_audit_logs   불변 감사 로그 (before/after JSONB)

  [규제 대응 & 시스템]
    regulatory_submissions  식약처 리콜 즉시보고 및 5일 이력정보 전송 증빙
    users                   사용자 (권한 5종: ADMIN/MANAGER/OPERATOR/QC/VIEWER)
    v_retention_deadlines   (뷰) 식품이력추적관리법 소비기한+2년 보관 의무


────────────────────────────────────────────────────────────────────────────
 6. 핵심 설계 개념
────────────────────────────────────────────────────────────────────────────

  ● 3-Way Match (구매 검증)
    발주(purchase_orders) → 입고(inbound) → 송장 을 연결하여
    "발주한 만큼 실제로 들어왔는지" 검증하는 SAP MM 핵심 개념.

  ● Batch Management (양방향 LOT 추적)
    - 역추적 : 완제품 → 생산LOT → 원재료LOT → 공급업체 (문제 원인 파악)
    - 순추적 : 공급업체 → 원재료LOT → 생산LOT → 출고처 (리콜 범위 파악)
    식품 안전 규정 대응의 핵심.

  ● Governance (거버넌스)
    AI 에이전트가 마음대로 데이터를 바꾸지 못하게,
    모든 액션을 권한(role)에 따라 승인/차단하는 통제 계층.
    → SAP GRC(거버넌스/컴플라이언스) 개념과 대응.


────────────────────────────────────────────────────────────────────────────
 7. AI 에이전트 시나리오 (우선 구현 3종)
────────────────────────────────────────────────────────────────────────────

  [Supply Chain Agent] 공급망
    - 유통기한 30일 이내 원재료 자동 감지 → 우선 사용 권고
    - 재고 소진 예측 → Procurement Agent에 재발주 요청

  [Procurement Agent] 구매
    - 공급업체 인증서 만료 30일 전 감지 → 담당자 알림
    - 납품 지연 감지 → 대체 발주 제안
    - 재발주 요청 수신 → 발주 Draft 생성 → 승인 요청

  [QC Agent] 품질관리
    - 알레르겐 미등록 원자재 입고 감지 → 입고 차단
    - 입고 온도 기준 이탈 감지 → 입고 보류
    - LOT 이상 감지 → 리콜 Draft 생성

  → 이 3개는 각각 실제 데이터(테이블)를 근거로 동작하므로
    "동작하는 데모"를 만들 수 있다.

────────────────────────────────────────────────────────────────────────────

  DB          : PostgreSQL 18 (DB명: mulino_coreano)

  에이전트    : Codex (Codex/Cowork) + 역할별 스킬
  프론트      : React 19 + Vite (대시보드)
  협업        : GitHub (모노레포)
